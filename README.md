# 病例学习智能体

面向临床医学本科二年级学生的病例题练习工具，覆盖《诊断学》《病理学》《内科学》三门课程。

核心功能是两件事：**自动命制病例单选题**，以及**对学生的作答做针对性的错因归因与解析**。

---

## 一、环境要求

- **Node.js 18 或更高版本**（不需要 npm，也不需要安装任何第三方依赖）
- 一个可用的大模型 **API Key**

项目默认对接 DeepSeek。如果你要用其他供应商，除了换 Key 和模型名，还需要改一处代码——`lib/model.js` 开头的接口地址。任何提供 OpenAI 兼容 `/chat/completions` 端点的服务都可以直接换过去。

项目刻意做成了零依赖：后端只用 Node 内置模块，前端是纯 HTML/CSS/JS，没有构建步骤。你不需要执行 `npm install`。

---

## 二、启动步骤

### 第 1 步：配置 API Key

把 `.env.example` 复制为 `.env`：

```powershell
copy .env.example .env
```

然后打开 `.env`，填入你的 Key：

```
API_KEY=你的真实key
MODEL=deepseek-chat
PORT=3000
```

### 第 2 步：启动服务

在项目根目录执行：

```powershell
node server.js
```

如果提示 `node` 不是可识别的命令，说明 Node 没有加入 PATH，改用完整路径启动。

看到下面的输出就说明启动成功：

```
  病例学习智能体已启动
  ----------------------------------------
  地址：http://localhost:3000
  模型：deepseek-chat
  疾病卡片：46 张（其中 46 张带考点）
  错因标签：7 个
  API Key：已配置
```

### 第 3 步：打开网页

浏览器访问 <http://localhost:3000>

按 `Ctrl + C` 可以停止服务。

### 换用其他大模型（可选）

项目默认对接 DeepSeek，但底层用的是 **OpenAI 兼容协议**（标准的 `/chat/completions`），所以任何提供该协议端点的服务都能换过去，不需要改动代码逻辑。

需要改两个地方。

**第一，`.env` 里的两项：**

```
API_KEY=你的新key
MODEL=新模型名
```

**第二，`lib/model.js` 里的接口地址那一行**（在文件里搜 `const ENDPOINT` 就能定位）：

```js
const ENDPOINT = 'https://api.deepseek.com/chat/completions';
```

改成你要用的那家服务的地址即可。

**两点需要注意：**

**不支持 JSON 模式的服务也能用，但稳定性会差一些。** 请求时会带上 `response_format: { type: 'json_object' }`，如果对方不支持，可能忽略也可能直接报错。但代码有兜底：解析失败时会剥掉 Markdown 代码块、截取首尾大括号之间的内容，再不行就带着错误信息重试一次。

**OpenAI 的新模型需要额外调整。** o 系列和 GPT-5 系列要求把请求体里的 `max_tokens` 换成 `max_completion_tokens`，直接切过去会被拒绝。要用这些模型，还得改 `lib/model.js` 里请求体的参数名。

## 三、怎么用

页面分三栏：左边是出题设置，中间是题目和结果，右边是学习画像。

**两种题型：**

- **病例题**：给出主诉、现病史、体格检查和辅助检查，让学生选择最可能的诊断，考查临床推理。
- **知识点题**：不设病例，直接考查对一个具体知识点的掌握，例如「关于甲状旁腺腺瘤，下列说法正确的是」。这类题目对病理学的肿瘤分类等内容尤其适用，因为那些考点天生没有病例。

知识点题还可以选择**单选**或**多选**。多选题会区分三种结果：完全正确、漏选、多选，并对漏选和多选给出不同的错因判断。

**两种练习模式：**

- **定向练习**：先选一个病种，针对性地反复练。适合刚学完某一章之后巩固。
- **随机测验**：只选课程，由系统随机抽一个病种，作答之前不告诉你考的是什么。适合检验自己是否真的掌握。

**每次答题的流程：**

1. 选择课程、模式、难度，点击「生成病例题」
2. 阅读病例（主诉、现病史、体格检查、辅助检查），选择你认为正确的选项
3. 点击「提交作答」
4. 查看三部分反馈：**错因归因**、**答案解析**、**鉴别要点**

如果题目涉及病理学内容，结果页还会额外附上该疾病的大体与镜下病理改变。

## 五、怎么扩充病种

只需要在 `data/diseases.json` 的 `cards` 数组里追加一张卡片，重启服务即可，代码不用改。

卡片字段说明：

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识，英文小写 |
| `name` | 疾病名称 |
| `type` | 可省略，省略即为 `disease`；纯概念类条目填 `concept` |
| `courses` | 该病属于哪些课程，取值必须是 诊断学 / 病理学 / 内科学 |
| `chapter` | 各课程下对应的章节，用于下拉框显示 |
| `symptoms` / `signs` | 典型症状与体征 |
| `keyTests` | 关键检查及其典型结果 |
| `diagnosticCriteria` | 诊断依据 |
| `pathology` | 供病理学出题使用；没有就填 `null` |
| `confusableWith` | **最关键的一项**：易混淆疾病及其鉴别点 |
| `commonMistakes` | 学生常见错误，用于约束干扰项设计 |

`confusableWith` 的质量直接决定了错因分析的质量：干扰项就是从这里挑的，鉴别点就是解析里给出的内容。

如果想为某个疾病补充可直接命题的考点，在 `data/knowledge.json` 的 `points` 里加上以疾病 id 为键的条目：

```json
"parathyroid_adenoma": [
  {
    "topic": "考点的名称",
    "correct": ["可以明确判断为真的陈述"],
    "wrong": ["学生常见的错误认知"]
  }
]
```

生成知识点题时，正确选项取自 `correct`，错误选项取自 `wrong`。如果某个疾病没有对应的考点条目，系统会自动退回从疾病卡片的病理、诊断依据、检查等字段中提取考点。

另外，像「血栓形成」「良性与恶性肿瘤的鉴别」「浆细胞」这类**不依附于任何具体疾病的纯概念**，也可以建成卡片：把 `type` 设为 `concept`，`symptoms`、`signs`、`keyTests`、`diagnosticCriteria`、`confusableWith` 留空数组，把考点写进 `knowledge.json` 即可。

这类条目只会出现在「知识点题」的病种列表里并标注「概念」，不会被用于命制病例题——因为它们没有病例可言。如果用概念条目请求病例题，服务端会返回明确提示而不是生成一道糟糕的题。

## 六、常见问题

**页面上提示「未检测到 API Key」**

`.env` 文件不存在，或者里面没有填 `API_KEY`。注意 `.env` 要放在项目根目录（和 `server.js` 同级），修改后需要重启服务。

**提交答案后提示「这道题的数据已经失效」**

题目数据保存在服务进程的内存里，重启服务后旧题目会失效。重新生成一道即可。

**返回 401 错误**

API Key 不正确。检查 `.env` 里有没有多余的空格或引号。

**返回 402 错误**

账户余额不足，需要先充值。

**生成的题目质量不稳定**

可以在 `lib/prompts.js` 里调整命题规则，或者降低「挑战」难度的使用频率。题目质量的下限主要由 `data/diseases.json` 里 `confusableWith` 的完整度决定。

**端口被占用**

在 `.env` 里把 `PORT` 改成别的值，例如 `3001`。

---

## 七、使用边界

本工具用于**教学练习**，所有内容由大模型生成，可能存在错误，不能作为临床诊断依据。

疾病卡片中的医学内容依据通行教材与诊疗共识整理，用于演示系统的知识约束机制，正式教学使用前建议由临床教师审校。
